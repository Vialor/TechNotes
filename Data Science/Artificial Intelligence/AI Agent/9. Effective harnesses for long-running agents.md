**问题：**长程任务需要agent跨对话session工作，两次session之间又没有共同记忆。需要找到一种方法，让 Agent 在从新的上下文窗口开始时能够快速理解工作状态。

**方法：**initializer agent + coding agent

# 具体问题

上下文管理能力仍不足以基于一个高层抽象的提示词完成完整的程序开发，会出现这两种情况：

1. Agent试图一次性解决所有问题，结果跑了一半上下文用完了，下一次session开始的时候看到的是一个实现了一半的功能，且没有文档

2. 等部分功能已经实现了，一个新的agent session进来，看到进度误以为事情已经做完了

3. 测试不彻底，就认为功能已完成了。通常是测通了unittest或者curl，不管端到端。

# 解决问题

## Initializer agent

第一次session时，agent根据一份特殊提示词设定好初始环境。环境包括：

1. init.sh: 运行开发服务器，免得模型找不到app入口

2. claude\-progress.txt：保存agent所做工作的日志

3. 初始 git 提交：哪些文件添加了？

4. feature\_list.json：全面的功能需求列表（Coding agent只能修改passes这一个字段）

```json
{
  "category": "functional",
  "description": "New chat button creates a fresh conversation",
  "steps": [
    "Navigate to main interface",
    "Click the 'New Chat' button",
    "Verify a new conversation is created"
  ],
  "passes": false
}
```

&emsp;&emsp;使用JSON是因为相比Markdown，JSON更不容易被不当修改。

## Coding agent

后续session，agent增量编写代码，一次session只实现一个功能。

模型改完代码离开环境的时候应保持环境干净，这点很关键。实现方式是通过模型提交git，并在claude\-progress.txt中记录进度的总结。由此模型可以使用git回退糟糕代码并恢复原本的代码环境。

这些也帮助agent掌握当前进度，不浪费时间重新调通基本的app。

Coding agent具体工作流：

1. 运行 `pwd` 确认工作目录，只能在此目录下改文件

2. 阅读 git 日志和进度文件，了解最新进展

3. 阅读功能列表，选择最高优先级的未完成功能

4. 实现功能并端到端测试  
提示词里面显式地给agent相关工具，并告诉它怎么像人一样操作。如在构建 Web 应用时，使用 Puppeteer MCP 服务器进行端到端验证。

5. 提交 git 并更新进度文件和功能列表
